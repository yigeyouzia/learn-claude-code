## 1. 为什么继续学习

HelloAgents 已提供知识基础，本课程重点转向运行时：模型如何提出工具调用，宿主如何执行、返回结果、管理上下文、保存任务状态与控制边界。基础概念优先回看已有笔记，新增内容重点记录源码、改动、失败与设计取舍。

完成这一轮学习后，应能解释并实现一个小型 Agent CLI，再把权限、状态、上下文与验收机制迁入自己的业务后端。FastAPI、SQL、RAG 评估和部署继续按照既有求职路线推进。

参考：[Agent 后端求职路线](../../../4-pinn-ts-agent/agent/roadmap/01-Agent后端求职学习路线.md)、[12 周计划](../../../4-pinn-ts-agent/agent/roadmap/02-12周学习计划.md)、[HelloAgents 笔记](../../../4-pinn-ts-agent/agent/hello-agents/README.md)。这些跨仓库链接依赖当前本地目录布局，GitHub 浏览时可能不可用；本次维护仅涉及当前 `notes/`。

## 4. 三周第一轮计划

每周建议投入 10–15 小时，时间仅作预算，按实际实验调整。第一轮可以完成概览与核心实验；复杂机制按验收结果继续深化。

| 阶段 | 阅读范围 | 交付与验收 |
| --- | --- | --- |
| 第 1 周 | 分类 01–03：s01–s07 | 最小循环 + 自制工具 + 权限与日志；跟踪一条完整调用，记录一次工具失败 |
| 第 2 周 | 分类 04–05：s08–s11 | 压缩前后信息对照、跨会话记忆记录、任务依赖与后台结果实验 |
| 第 3 周 | 分类 07–08：s14–s17；分类 06 概览 | 追踪集成流程；完成一个中断续跑或目标验收实验；给未覆盖机制留下 TODO |
| 第二轮 | s08、s10、s11、s15、s16、s17 及项目所需机制 | 修补失败路径，接入真实业务后端；按需深入 s12、s13 |

每周默认分配：约 25% 阅读与看图、55% 编码调试、20% 笔记和口头复盘。遇到基础缺口时回查 HelloAgents 对应章节，不重新抄写整套课程。

## 5. 本地源码、网页与笔记怎样配合

```text
提出问题与预期结果
    ↓
网页学习页 / 图示 / 模拟：先建立流程直觉
    ↓
本地 README.zh.md：确认本地版本的机制、边界和运行入口
    ↓
本地 code.py：模型调用 → 工具分发 → 结果写回 → 状态与退出路径
    ↓
运行原示例 → 修改一个行为 → 构造失败 → 检查证据
    ↓
分类笔记：结论 + 来源 + 实验 + 取舍 + 下次起点
```

### 5.1 使用网页版教程

先带一个问题看学习页，再用模拟观察消息、工具结果和状态变化。模拟只用于理解，不能记为本地程序已复现。网页源码与本地代码有差异时，在对应笔记记录日期、版本、差异和结论适用范围。

若需要与本地版本一致的网页，可在确有需求时按根 README 运行 `web/` 开发服务；学习笔记维护不自动安装依赖或启动服务。

### 5.2 阅读本地源码

先找入口、状态、工具定义与 handler，再看本章新增机制及其调用位置。可以从仓库根目录执行：

```sh
git rev-parse HEAD
rg -n '^def |^class |^async def ' s02_tool_use/code.py
rg -n 'agent_loop|TOOL_HANDLERS|tool_use|tool_result' s02_tool_use/code.py
```

对每个关键机制回答：在哪里调用？修改了什么状态？失败怎样返回？谁决定继续或停止？行号可辅助定位，长期笔记应以路径、符号名和 commit 为主。

不要默认每章都是上一章的完整累积版本：s14 从基础工具与 Hooks 接入 MCP，s15 再集成多种机制；s17 用独立的较小运行时讲目标控制。

### 5.3 开展实验

依赖与环境变量参照根 README、`requirements.txt` 和 `.env.example` 的字段说明；不把真实密钥写进笔记。运行前检查章节怎样取得 `WORKDIR`、加载配置和保存状态；从临时工作目录运行时尤其确认配置是否仍能正确加载。

教学 Shell 工具可以执行模型生成的命令。实验使用一次性测试目录与模拟文件，先检查权限路径；字符串拒绝列表、worktree 或消息隔离不能视作完整安全沙箱。

原课程代码默认作为对照基线；自己的修改实验按需放入 `notes/experiments/<分类编号>/`，图示放 `notes/assets/<分类编号>/`。只有实际需要才创建这些目录。该约定不会自动改变课程运行时的落盘位置，实验中仍需核查实际路径。

### 5.4 编写自制笔记

先用自己的话说明问题，再补调用链和证据。正文区分“来源事实”“理解总结”“工程建议”“待验证假设”。代码只摘机制所需片段，完整实现用源码链接定位。

每个分类至少积累：一张流程或状态图、一条关键调用链、一个修改实验、一个失败案例及三道自测题。多章节分类逐章记录，概览阶段允许实验待运行，不能提前勾选完成。

## 6. 全课程验收与项目衔接

- [ ] 独立说明模型决策与宿主执行的分工，写出最小 Agent Loop。
- [ ] 实现自制工具，说明参数、权限、结果和错误的处理位置。
- [ ] 对照压缩前后历史，检查目标、约束和关键证据是否保留。
- [ ] 区分上下文、记忆、Todo、持久任务状态和恢复 journal。
- [ ] 证明后台任务已完成，而非仅取得启动 ID。
- [ ] 理解模拟 MCP 与真实 Client/Server transport 的差异。
- [ ] 根据日志追踪一次集成执行，解释取消、失败与停止条件。
- [ ] 完成一个续跑或客观验收实验，并说明局限。

迁入求职项目时优先选权限校验、持久任务状态、后台文档处理与可观测验收。多 Agent、Cron、复杂编排按需求引入。简历中的时延、成本、成功率等数据必须来自真实测量。
